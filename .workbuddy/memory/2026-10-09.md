## 在 192.168.0.115 (Ubuntu 26.04, amd64) 上安装 Consul

- 方式：Docker（percy 用户在 docker 组，免 sudo）。
- 镜像：因 Docker 守护进程代理 `/etc/systemd/system/docker.service.d/proxy.conf` 指向死代理 `192.168.0.119:7890`（不可达，导致 `docker pull` 全部失败），改用离线构建：直连下载 `consul_1.21.0_linux_amd64.zip`（releases.hashicorp.com 可直连）→ `FROM scratch` + COPY 二进制 → `docker build` 出 `consul:1.21.0`（无网络依赖）。
- 容器：`consul`，`--restart unless-stopped`，server 模式 `bootstrap_expect=1`、UI 开启。
- 端口映射：8500(UI/HTTP API)、8600(DNS/udp)、8300-8302(server/gossip)。
- 数据卷：`/home/percy/consul/data`（持久化）、配置 `/home/percy/consul/config/consul.json`。
- 验证：members alive、leader 已选、UI HTTP 200、DNS 解析 `consul-server-1.node.dc1.consul` 返回 192.168.0.115。

## dashboard 移除 MyBatis / 迁移 Spring Data JDBC + 双库兼容

- 现状：上一轮已删掉 `MyBatisNativeConfiguration.java`、`GeneralMapper.java`、XML 与 `schema.sql`，pom 改为 `spring-boot-starter-data-jdbc`，实体用 `@Table/@Id/@Column`、Repository 用 `CrudRepository` + `@Query`（Spring Data JDBC，非 JPA）。
- 本轮修复的卡点/坑：
  1. `AutumnDashboardGatewayApplication.main` 写成 `static void main`（缺 `public`）→ JVM 找不到入口，启动必崩；已补 `public`。
  2. `user` 是 SQL 保留字，Spring Data JDBC 派生查询/save/delete 自动生成 `FROM user` 在 MySQL/PG 都报保留字错误。新增 `config/JdbcConfig.java`，用 `NamingStrategy` 给表名统一加双引号；PG 原生支持，MySQL 靠 `application-mysql.properties` 里的 `ANSI_QUOTES`（`sessionVariables=sql_mode='ANSI_QUOTES'`）配合。注意：`user` 表被 `autumn-gateway-authorization` 模块共享，**不能改名**。
  3. `UserService.listRolesByUserId` 有 NPE：`List<Role> roles = null` 后 `roles::add`；改为 `new ArrayList<>()`。
  4. `schema-postgresql.sql` 原先用 `ALTER TABLE ADD CONSTRAINT` 加外键 + 裸 `CREATE INDEX`，在 `spring.sql.init.mode=always` 下二次启动会报"约束/索引已存在"；已改为建表内联 FK + `CREATE INDEX IF NOT EXISTS`，与 MySQL 版一样幂等。
- 验证：`./mvnw -o -pl autumn-gateway-dashboard -am compile` 通过。
- 切换数据库：`--spring.profiles.active=mysql`（默认）或 `postgresql`；分别用 `application-mysql.properties`/`application-postgresql.properties` + `schema-mysql.sql`/`schema-postgresql.sql`。
- 注意：MySQL url 指向 `192.168.1.16:3306/autumn-security`，PG 指向 `localhost:5432`，按需改。
