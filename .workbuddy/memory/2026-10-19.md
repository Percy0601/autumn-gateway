## 操作日志拦截器（写入 basic_oper_log）
- 需求：拦截所有 POST/PUT/DELETE 写操作记录到「日志管理」表 basic_oper_log（用户给了拦截器统一拦截 / AOP 注解两种方向，选了拦截器）。
- 新增 4 个文件（`autumn-gateway-dashboard/src/main/java/xyz/wewin/autumn/gateway/dashboard/`）：
  1. `config/OperLogCachingFilter.java`：最高优先级 `OncePerRequestFilter`，对 JSON 写请求（POST/PUT/DELETE/PATCH + application/json）包 `ContentCachingRequestWrapper`，使 body 可重复读。
  2. `config/OperLogInterceptor.java`：`HandlerInterceptor`，`afterCompletion` 里仅对 `HandlerMethod` 的 POST/PUT/DELETE、URI 以 `/api` 开头且非鉴权（/login,/auth,/oauth,/token）的写操作落库；从 `RequestContext.currentUserId()` 取操作人，按 `/api/system/basic/<module>` 解析模块名，字段按列长截断（2000/200/100/50），异常或 HTTP≥400 置 status=1。
  3. `service/OperLogRecorder.java`：`@Transactional(REQUIRES_NEW)`，审计日志独立事务，业务回滚也不丢；写失败由调用方 catch，不影响主流程。
  4. `config/OperLogConfig.java`：`WebMvcConfigurer`，把拦截器注册到 `/api/**`。
- 选 HandlerInterceptor 而非原始 Filter 的原因：它在 DispatcherServlet 内、JWT 过滤器清理 RequestContext 之前执行，能可靠拿到操作人、响应码、异常，且天然避开静态资源/GET/404。
- 编译踩坑（Spring Boot 4 / Spring Web 7.0.9）：`ContentCachingRequestWrapper` 已从 `org.springframework.web.filter` **迁移到 `org.springframework.web.util`**，且构造器改为必须传 `int maxContentLength`（对齐旧默认 1MB）。已修正 import + `new ContentCachingRequestWrapper(request, 1024*1024)`。
- `./mvnw -pl autumn-gateway-dashboard -am clean compile` 已通过（4 个 class 生成成功）。运行时仍需 102 上 MySQL 起来（约 40s SQL 初始化）后才会真正写库，可在「日志管理」页面查看。
