### H2 标识符大小写踩坑（核心）
`JdbcConfig` 只给**表名**加双引号（小写，来自 `@Table`），而 Spring Data JDBC 给**列名**也加引号，且：
- 未标注 `@Column` 的字段 → 生成 **大写**（`"IDENTIFIER"`、`"ID"`）
- 标注 `@Column("user_id")` 的字段 → 保持 **小写**（`"user_id"`）

H2 对**带引号**标识符大小写敏感，裸写标识符则按 `DATABASE_TO_UPPER` 默认转大写。因此：
1. `schema-h2.sql` 里 `user`/`user_app`/`user_auth_account`/`application`/`permission`/`role` 等表必须**按上面规则逐列加引号**创建；
2. 裸写 `@Query`（如 `FROM user_app`）不会被 `JdbcConfig` 改写 → 也要把表名和**小写列**（`app_id`、`perm_type`、`appid`、`user_id`…）加引号。大写列（`ID`/`NAME`/`CODE`）可保持裸写，三库都能匹配；
3. **不要**加 `DATABASE_TO_LOWER=TRUE`（会把大写列变小写，反而崩）；
4. 删除各表 FOREIGN KEY（避免跨表大小写引用不一致），本地演示无需参照完整性；
5. `TINYINT` → `BOOLEAN`：`user_app.is_admin`、`user_auth_account.verified`（H2 返回 Integer，Spring 无 Integer→Boolean 转换器；MySQL 驱动会自动转所以没问题）。
> 共享 Java 代码里不要用大写引号（如 `ORDER BY "ID"`），PostgreSQL 会把裸标识符折叠成小写、匹配不上；统一裸写 `id`。

验证通过：登录 `POST /api/login/account` → `{status:ok, token}`；`/api/currentUser` → `access=admin`；
`/api/system/basic/{app,user,role,menu,resource,group}` 与 `/api/system/app/list`、`/api/system/permission/list` 全部 200 带数据。

## 前端：修复"循环登录 / 不停登录"（auth store 重复 + userid 映射）

现象：后台能收到 `/api/login/account` 请求并返回 `{status:ok,token}`，但前端在登录页与受保护页之间无限跳转（循环登录）。

### 根因（两处）
1. **重复的 `useUserStore`**：登录页 `src/views/login/index.vue` 引用 `@/stores/user`（上一轮误建的同名 store，id=`user`），而**路由守卫** `src/router/index.ts` 用的是 `@/store/modules/user`（id=`userStore`，才是真正对接守卫/Navbar 的 auth store）。登录把 token 写进"假 store"，守卫读"真 store"永远为空 → 判定未登录 → 无限重定向 `/login` ↔ 受保护页。
2. **`userid` ≠ `id`**：守卫用 `!userStore.user.id` 判断是否已拉取用户信息；后端 `/api/currentUser` 返回 `userid`（无 `id` 字段），`getUserInfoAction` 合并后 `user.id` 始终为空 → 每次导航都重拉 currentUser + 重建路由 → 再次循环。

### 修复
- `src/views/login/index.vue`：import 改为 `@/store/modules/user`（与守卫同一 store）。
- 删除重复的 `src/stores/user.ts`（仅被旧登录页引用，删后无残留引用）。
- `src/store/modules/user.{ts,js}` 的 `getUserInfoAction`：合并时补 `id: body.data.userid ?? body.data.id ?? this.user.id`，使守卫 `!user.id` 翻转为 false，跳出循环。
- `store/modules/user` 的 `accountLoginAction` 已自带 `type:'account'` 并写 token+localStorage，登录流程无需再造。

### 验证
- `vite build`：`✓ 2664 modules transformed`（全部模块编译/解析正常）。唯一"失败"是沙箱 `SAFE_DELETE_BULK_CONFIRM_REQUIRED` 在 `emptyDir dist/`（删 50+ 文件触发），与代码无关，用户跑 `dev` 不受影响。
- `vite` dev：`ready` 无报错；`login/index.vue`、`store/modules/user.js`、`router/index.ts` 均 HTTP 200；served login.vue 的 import 解析为 `/src/store/modules/user.js`，`stores/user` 出现 0 次。
- 后端 `LoginController` 免密兜底改动 `mvnw -pl autumn-gateway-dashboard compile` 通过（exit 0）。`./mvnw` 在仓库根目录，不在 dashboard 子目录。

### 易复发提醒
- 不要把登录/守卫用到的 auth store 拆成两个；本工程唯一权威 auth store 是 `src/store/modules/user`（Pinia id=`userStore`）。
- 后端 `/api/currentUser` 返回 `userid` 而非 `id`；前端取用户主键务必用 `userid`（已在 `getUserInfoAction` 兼容）。
