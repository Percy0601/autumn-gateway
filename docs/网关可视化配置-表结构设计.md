# 网关可视化配置 — 表结构设计

> 目标：dashboard 已经管好 用户/角色/菜单/权限，下一步把**网关自身**也搬进数据库可视化维护。
> 流程：页面配置 → 落库 → 导出 properties/yaml → 同步到本地文件 / Consul（Nacos 暂不支持，见 §6.3）。
>
> 配套 DDL（三份，MySQL / PostgreSQL / H2，结构一致）：
> `autumn-gateway-dashboard/src/main/resources/db/gateway/gw_schema_{mysql,postgresql,h2}.sql`

---

## 0. 口径校准（先记住这条，否则导出即失效）

仓库实际版本：**Spring Boot 4.1.1 + `spring-cloud-starter-gateway-server-webflux` 5.0.3**（根 `pom.xml`）。

SCG 5 把 server-webflux 的所有配置收进**新前缀**，旧写法在 SCG 5 里不再生效：

| 配置对象 | 旧前缀（文档误用） | **SCG 5 正确前缀** |
|---|---|---|
| 路由列表 | `spring.cloud.gateway.routes[i]` | `spring.cloud.gateway.server.webflux.routes[i]` |
| 默认过滤器 | `spring.cloud.gateway.default-filters` | `spring.cloud.gateway.server.webflux.default-filters[i]` |
| HTTP 客户端 | `spring.cloud.gateway.httpclient.*` | `spring.cloud.gateway.server.webflux.httpclient.*` |
| CORS | `spring.cloud.gateway.globalcors.*` | `spring.cloud.gateway.server.webflux.globalcors.*` |
| Netty 服务端 | — | `spring.cloud.gateway.server.webflux.httpserver.*` |
| 转发头 | `spring.cloud.gateway.x-forwarded.*` | 已移除，改为单值 `...server.webflux.trustedProxies`（可信代理正则） |

证据：`GatewayProperties.PREFIX = "spring.cloud.gateway.server.webflux"`（jar 源码）；
仓库内 `autumn-gateway-deploy/src/main/resources/application.properties` 第 18~36 行已经全部用新前缀。
`ConsulRouteDefinitionLocator.PREFIX` 也已经是 `"spring.cloud.gateway.server.webflux.routes"`。

**另外两条硬约束（决定了 args 只能扁平化）：**

- `RouteDefinition` 字段：`id / predicates / filters / uri / metadata / order / enabled`。
  `enabled` 是 SCG 5 原生字段 → `gw_route.status` 直接映射它，不用再靠「停用就不导出」来实现。
- `FilterDefinition` / `PredicateDefinition` = `name` + `Map<String,String> args`。
  **args 的值只能是字符串**，嵌套对象/list 无法用配置表达（见 §4.3 对 `MemoryRateLimiter` 的影响）。

### 1.2 路由（每个下游服务）配置

对应 `spring.cloud.gateway.server.webflux.routes[i]`，一条路由 = 一个下游服务：

| 字段 | 必填 | 唯一 | 形态 |
|---|---|---|---|
| route id（`route_code`，如 `order-service`） | 是 | **全局唯一** | 标量 |
| 路由名/备注 | 否 | — | 标量 |
| 绑定 app_code（关联 `basic_app.app_code`） | 否 | 可空 | 下拉单选 |
| uri（`lb://x` 或 `http://host:port`） | 是 | 每路由一个 | 标量 |
| order（越小越先匹配） | 否（默认 0） | — | int |
| predicates | **至少一个** | list | 可增删行，之间 AND |
| filters | 否 | list | 可增删行，带顺序 |
| metadata | 否 | map | KV |
| **enabled**（← `gw_route.status`） | 是 | — | switch，SCG 5 原生支持**关闭单条路由** |

### 1.3 断言（predicate）类型

| 工厂 | 参数（args key） | 备注 |
|---|---|---|
| Path | `pattern`（逗号分隔多模式） | 多条 Path 之间是 AND，通常一条足够 |
| Method | `methods` | |
| Host | `pattern` | |
| Header | `header` + `regexp` | |
| Query | `param` + `regexp`(可选) | |
| Cookie | `name` + `regexp` | |
| Between | `datetime1` + `datetime2` | |
| RemoteAddr | `sources`（CIDR 列表） | |
| Weight | `group` + `weight` | 需同一 group 配对使用 |

### 1.4 过滤器（filter）类型

**路由级**（`GatewayFilterFactory`）——本仓库真实注册的只有两个：

| 工厂 | 真实名称 | args | 每路由唯一性 |
|---|---|---|---|
| 认证/鉴权 | **`Authz`** | `mode`(authenticate/authorize)、`appCode`、`permitAll`、`failOpen` | singleton（语义上重复只能是配置错误） |
| 限流（Bucket4j 内存） | **`MemoryRateLimiter`** | `keyType`(IP/HEADER/PATH)、`headerName`、`replenishRate`、`burstCapacity`、`timeWindowSeconds`、`antPathConfigs` | singleton |
| — | AddRequestHeader / AddResponseHeader | `name`、`value` | **可重复** |
| — | StripPrefix / PrefixPath / RewritePath / SetPath / SetStatus / RedirectTo / RequestSize / Retry / CircuitBreaker / TokenRelay | 见各自 Config | 视工厂而定 |

> 修正点：原稿写「RequestRateLimiter（本项目 MemoryRateLimiter）」会误导。本仓库**没有**
> `RequestRateLimiter`（没有 `KeyResolver`、没有 Redis 限流），只有 `MemoryRateLimiterGatewayFilterFactory`，
> 短名即 `MemoryRateLimiter`；`AuthzGatewayFilterFactory.Config` 也有 4 个字段，不止 `mode`+`appCode`。

**全局级**：注意区分两个概念。

- `default-filters`（**配置驱动，可以由表数据产生**）：`spring.cloud.gateway.server.webflux.default-filters[i]`，
  作用在每条路由上 → 这就是 `gw_global_filter` 的落点。
- `GlobalFilter` Bean（**代码驱动，无法由表数据产生**）：本仓库 starters 里**一个都没有**。
  `AuthzGatewayFilterFactory` 的类注释明确写了「不注册 GlobalFilter」。
  examples 模块里的 `TraceGlobalFilter` / `AuthHeaderGlobalFilter` / `CommonFilter` 属于示例。

因此原稿里那张「真实 IP 解析 / 灰度 / CORS / 链路追踪 / 统一包装」的全局过滤器清单，
在当前仓库**不存在对应实现**，只能作为「后续功能 + 对应配置项」的规划，不该当作已有能力盘点。

## 2. 页面交互语义

四种配置形态，前端按 schema 渲染（schema 来源见 §3）：

| 形态 | 含义 | 例子 | 前端控件 |
|---|---|---|---|
| scalar-required | 不填不让提交 | `route.uri`、`jwt.secret`、Authz 的 `mode`+`appCode` | 输入框 + 必填红星 |
| scalar-optional-singleton | 最多一个，可留空 | `server.port`、`Authz.failOpen` | 输入框，留空走代码默认值 |
| singleton-per-route | 一条路由下只准出现一次 | `Authz`、`MemoryRateLimiter`、`StripPrefix`、`TokenRelay` | 已挂过的工厂在下拉里置灰 |
| list-repeatable | 同一过滤器可挂 N 次 | AddRequestHeader、多个 Header 断言、`permit-all` | 动态行表格 |

边界规则同样由 schema 驱动，不硬编码：

- `required`：哪些参数必填（`Authz` 有参、`TokenRelay` 无参）。
- `sensitive`：加密落库 + 页面掩码（`jwt.secret`、`client-secret`、`spring.datasource.password`、consul token）。
- `textarea`：`autumn.authz.sql.*` 这类大文本。

## 3. 表结构

### 3.1 现状（DDL 已落地，5 张表，`gw_` 前缀）

```
gw_config_item       全局 key-value 配置（profile_code 一列做环境隔离）
gw_route             路由（每个下游服务一行）
gw_route_predicate   路由断言（1 : N）
gw_route_filter      路由过滤器（1 : N，sort_num 定顺序）
gw_global_filter     默认过滤器 default-filters（带顺序）
```

### 3.2 候选（设计取舍未定，见 §6.1）

```
gw_config_profile        环境表（CONSUL/NACOS 地址、dataId、group、ACL token）
gw_filter_definition     过滤器字典（工厂元数据 + 动态表单 schema）
gw_predicate_definition  断言字典
gw_config_publish        发布记录（导出/推送的审计与回滚快照）
```

### 3.3 核心字段

**gw_config_item**
`id, profile_code, config_group, config_key, config_value, value_type, is_required, is_encrypted, sort_num, remark, created_at, updated_at`
唯一键 `uk_gw_item_profile_key (profile_code, config_key)`。
`value_type` 取值：`STRING/INT/LONG/BOOL/DURATION/LIST/JSON/TEXTAREA`。
`config_group`：`SERVER / DATASOURCE / SCG / AUTHN / AUTHZ / LIMIT / CORS / CONSUL / CUSTOM`。

**gw_route**
`id, route_code(唯一), route_name, app_code, uri, order_num, metadata_json, status, del_flag, remark, created_at, updated_at`
`status=0` → 导出为 `routes[i].enabled=false`；`status=1` → `enabled=true`。

**gw_route_predicate / gw_route_filter**
`id, route_id, {predicate_name|filter_name}, args_json, sort_num, status, del_flag, created_at, updated_at`

**gw_global_filter**
`id, filter_name, args_json, sort_num, enabled, status, del_flag, remark, created_at, updated_at`

### 3.4 取舍说明

1. **args 用 `args_json` 存 JSON**：SCG 每个工厂参数不同，EAV 竖表会 join 爆炸；导出时按工厂名翻译成
   `name=`/`args.xxx=` 形式（见 §4.2）。
2. **软删 + 唯一键不含 `del_flag`**：`route_code` 删掉后再建同名编码会被唯一键挡住，
   恢复的正确姿势是 `UPDATE del_flag=0` 复活，「新建同名」要走「重命名已有记录」。
   > 注意：别再说「沿用 basic_* 那套」——basic_* 本身就不统一：
   > `basic_namespace` 没有删除列、`basic_group` 用 `deleted INT`、`basic_user` 用 `del_flag`、
   > `basic_menu_resource` 用 `deleted`。gw_* 统一用 `TINYINT del_flag` 只是**本项目新表的约定**。
3. **路由不按环境拆**：dev/test/prod 共用一份路由差异靠注册中心或 uri 占位符，只有全局标量按 profile 隔离。
   > 风险：仓库现状 `uri=http://localhost:8081` 是写死地址，不是 `lb://`。
   > 一旦出现「同一服务在 dev 走 IP、prod 走注册中心」，这条取舍就不成立 → 备选方案见 §6.2。
4. **`gw_config_item` 目前不能删除/停用单行**：没有 `del_flag`/`status`。页面若允许新增自定义 key，
   就必须同时给删除能力，否则页面上的无效 key 永远跟着导出。建议补 `del_flag`。

## 4. 导出与同步映射规则（原稿缺失，且是最关键的一环）

### 4.1 一份配置的组成

```
导出(profile) = gw_config_item(profile_code = p) 全部有效行
              + gw_global_filter 全部启用行            → default-filters[i]
              + gw_route(del_flag=0) 全部行            → routes[i]
                └ gw_route_predicate / gw_route_filter → routes[i].predicates[j] / .filters[j]
```

### 4.2 properties 导出规则

1. **标量**：`config_key = config_value`。`is_encrypted=1` 的字段导出时**解密**后写入，
   并在导出界面单独提示「本次导出含明文密钥」。
2. **必须用长写 `name=` + `args.` 形式，不要用短写**。
   短写（`Authz=authenticate,dashboard`）依赖 `shortcutFieldOrder()`，参数少一个、值里含逗号/冒号都会解析错或用错位置：

   ```properties
   spring.cloud.gateway.server.webflux.routes[1].id=dashboard-api
   spring.cloud.gateway.server.webflux.routes[1].uri=http://localhost:8081
   spring.cloud.gateway.server.webflux.routes[1].order=-100
   spring.cloud.gateway.server.webflux.routes[1].enabled=true
   spring.cloud.gateway.server.webflux.routes[1].predicates[0].name=Path
   spring.cloud.gateway.server.webflux.routes[1].predicates[0].args.pattern=/api/**
   spring.cloud.gateway.server.webflux.routes[1].filters[0].name=Authz
   spring.cloud.gateway.server.webflux.routes[1].filters[0].args.mode=authenticate
   spring.cloud.gateway.server.webflux.routes[1].filters[0].args.appCode=dashboard
   ```
   项目里 `AuthzGatewayFilterFactory.shortcutFieldOrder() = [mode, appCode]`，
   `MemoryRateLimiterGatewayFilterFactory.shortcutFieldOrder() = [replenishRate, burstCapacity, timeWindowSeconds]`
   ——正是容易写错的地方。
3. **索引必须从 0 连续**：按 `order_num` 排序后重编 `i`；predicates/filters 同样按 `sort_num` 重编 `j`。
4. **LIST 值**（`permit-all`、`scope`、`methods`）在 properties 里是逗号分隔字符串；
   **TEXTAREA 值**（`autumn.authz.sql.*`）含换行，properties 要 `\` 续行转义，稍有不慎整份文件就废了
   → **含 SQL 的配置推荐导出 yaml，而不是 properties**。
5. `is_required=1` 且值为空 → 导出前校验失败，不让导出。

### 4.3 yaml 导出规则

结构同 §4.2，注意两点：

- `args` 的类型是 `Map<String,String>`，yaml 里**值一律加引号**，
  否则 `1分钟`、`真`、`=`、前导零这类值会被 snakyaml 解析成别的东西。
- `metadata` / `routes[i].metadata.xxx` 同理：值转字符串。

**已知不可导出项**：`MemoryRateLimiter` 的 `antPathConfigs` 是嵌套 List 对象，
配置（properties/yaml）无法表达，只能靠 Java DSL 或改造成逗号分隔的扁平串。
v1 页面不暴露这个参数，并在导出时忽略。同理受限的还有 CircuitBreaker/Retry 里的嵌套 config。

### 4.4 同步目标

| center_type | 现状 | 同步方式 |
|---|---|---|
| **FILE** | 可用 | 直接写 `autumn-gateway-deploy/src/main/resources/application.properties` 或下载 |
| **CONSUL** | 可用（本仓库 `config-discovery-autumn-gateway` 已实现 Consul Config Data Loader） | Consul KV HTTP API：`PUT /v1/kv/{prefix}/{dataId}`，value 是 properties/yaml 文本；需要 ACL 时 profile 表要有 token 字段 |
| **NACOS** | **不可用** | 全仓库 pom 里没有任何 nacos 依赖（`Get-ChildItem -Include pom.xml` 搜 `nacos` 零命中）。要么 v1 先砍掉，要么先引依赖再谈 |

### 4.5 生效方式（别指望写完就自动生效）

- `routes` 走 `Environment` 绑定，改完要触发 `RefreshEvent` / `EnvironmentChangeEvent` 或重启。
- 仓库里 `config-discovery-autumn-gateway-starter-using` 的 `ConsulRouteDefinitionLocator`
  演示了「Consul KV → 路由热更新」，但它**只读 `predicates[0]` 和 `filters[0]`**
  （见该类第 49~56 行）——多断言/多过滤器的路由会被静默截断。
  要做「动态下发」就必须先把它改成按索引循环读取，否则一张表里配了好几个 predicate 也只有一个生效。

## 5. 页面交互 → 存储的落点总表

| 页面 | 表 | 关键约束 |
|---|---|---|
| 全局配置（按环境切换） | `gw_config_item` | `(profile_code, config_key)` 唯一；敏感字段掩码；TEXTAREA 单独大框 |
| 路由列表 | `gw_route` | `route_code` 唯一；`status` → `enabled` |
| 路由详情-断言 | `gw_route_predicate` | 至少一条；AND 关系要写在界面提示里 |
| 路由详情-过滤器 | `gw_route_filter` | `sort_num` 决定链顺序；singleton 工厂靠 schema 拦截 |
| 全局默认过滤器 | `gw_global_filter` | → `default-filters[i]` |
| 导出/推送 | — | 先按 §4.2 校验 → 生成文本 → 下载或 PUT 到 Consul |
| 发布历史/回滚 | `gw_config_publish`（候选） | 当前 DDL 无此表，v1 无回滚能力 |

## 6. 待定事项（需要拍板，暂未改 DDL）

### 6.1 要不要 `gw_filter_definition` / `gw_predicate_definition` 字典表

现有 DDL 刻意不建，理由写在文件头：「过滤器工厂是 Spring Bean，新增必须改代码，参数 schema 放代码侧静态注册表」。
这话只对一半——新增工厂确实要改代码，但**参数 schema 落库的好处是加字段改个 JSON 就行、不用发版**。

倾向：**保持代码侧静态注册表**（一份 Java 常量 + 一个 `/api/gw/filter-definitions` 接口返回给前端），
理由是字典表会和 Factory 的 Config 类产生「两份真相」，代码改了表没改就是脏数据；
真要热插拔，把 Config 类做成 Map-based 再谈。

### 6.2 路由要不要加 profile 维度

现状 §3.4-3 的取舍在「同一服务不同环境不同 uri」场景下会崩。三种改法，二选一即可：

- A：给 `gw_route` 加 `profile_code`，按环境各存一套（表变重，但语义直白）；
- B：保持一套，`uri` 支持占位符 `${order.host}`，环境变量按 profile 注入（改动最小，推荐）。

### 6.3 发布记录与 Nacos

- `gw_config_publish`：要想「推错了能回滚」，这张表必须有，否则一次误推只能手动重写。
  建议 v1.1 补上，`snapshot_json` 存当次导出的全文。
- Nacos：当前不可支持，`center_type` 枚举先只留 `FILE / CONSUL`，别在设计图上画出没接线的插头。

### 6.4 其他待修
