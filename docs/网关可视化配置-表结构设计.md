# 网关可视化配置 — 表结构设计

> 目标：dashboard 已经管好 用户/角色/菜单/权限，下一步把**网关自身**也搬进数据库可视化维护。
> 流程：页面配置 → 落库 → 导出 properties/yaml → 同步到本地文件 / Consul / Nacos。
>
> 本文配套 DDL：`autumn-gateway-dashboard/src/main/resources/db/gw_schema_mysql.sql`

---

## 1. 常规配置项盘点（从代码里实际抠出来的）

按"作用域"分三类：**全局标量配置**、**路由（每个服务）配置**、**过滤器/断言实例**。

### 1.1 全局标量配置（key-value，按环境隔离）

来源：`AuthnGatewayProperties` / `AuthzGatewayProperties` / `LimitAutumnGatewayProperties` / Spring Cloud Gateway 自身。

| 配置项 key | 类型 | 必填 | 唯一 | 说明 |
|---|---|---|---|---|
| `server.port` | int | 是 | singleton | 网关端口 |
| `spring.application.name` | string | 是 | singleton | 固定 autumn-gateway |
| `autumn.authn.enabled` | bool | 是 | singleton | OAuth2 客户端总开关 |
| `autumn.authn.registration-id` | string | 否 | singleton | 默认 web-client |
| `autumn.authn.client-id` / `client-secret` | string | authn 开启时必填 | singleton | secret 加密存储 |
| `autumn.authn.issuer-uri` | string | authn 开启时必填 | singleton | 授权服务器地址 |
| `autumn.authn.scope` | string(list) | 否 | singleton | 逗号分隔，值本身是 list |
| `autumn.authn.redirect-uri-template` | string | 否 | singleton | |
| `autumn.authn.logout-url` / `logout-success-url` | string | 否 | singleton | |
| `autumn.authn.permit-all` | **list** | 否 | singleton（值是 list） | 匿名放行路径，多行 |
| `autumn.authz.enabled` | bool | 是 | singleton | 鉴权总开关 |
| `autumn.authz.app-code` / `login-app-code` | string | 是 | singleton | 兜底应用编码 |

| `autumn.authz.jwt.issuer` | string | 否 | singleton | |
| `autumn.authz.jwt.ttl-seconds` | long | 否 | singleton | 默认 86400 |
| `autumn.authz.headers.user-id/username/roles` | string | 否 | singleton | 下游身份头名 |
| `autumn.authz.captcha.enabled/length/ttl-seconds/cookie-name` | mixed | 否 | singleton | 验证码 |
| `autumn.authz.sql.*` | **textarea** | 否 | singleton（值是大文本 SQL） | 五段 SQL，带列别名契约 |

### 1.2 路由（每个下游服务）配置

对应 `spring.cloud.gateway.routes[i]`，一条路由 = 一个下游服务：

| 字段 | 必填 | 唯一 | 形态 |
|---|---|---|---|
| route id（如 `order-service`） | 是 | **全局唯一** | 标量 |
| 路由名/备注 | 否 | — | 标量 |
| 绑定 app_code（关联 basic_app） | 否 | 可空 | 下拉单选 |
| uri（`lb://order-service` 或 `http://host:port`） | 是 | 每路由一个 | 标量 |
| order（路由顺序，越小越先匹配） | 否（默认0） | 每路由一个 | int |
| 断言列表 predicates | **至少一个** | **list** | 可增删行 |
| 过滤器列表 filters | 否 | **list** | 可增删行，带顺序 |
| metadata（透传元数据） | 否 | map | JSON |
| status（启用/停用） | 是 | — | switch |

### 1.3 断言（predicate）类型

| 工厂 | 参数形态 | 是否可多条 |
|---|---|---|
| Path | pattern（逗号分隔多模式） | 通常一条，可多条 |
| Method | GET,POST,... | 一条 |
| Host | `**.example.com` | 可多条 |
| Header | name + regexp | 可多条 |
| Query | param + regexp(可选) | 可多条 |
| Cookie | name + regexp | 可多条 |
| Between | 两个时间 | 一条 |
| RemoteAddr | CIDR 列表 | 可多条 |
| Weight | group + weight | 一条（负载均衡组） |

### 1.4 过滤器（filter）类型

路由级（GatewayFilterFactory）：

| 工厂 | 参数 | 每路由唯一性 | 可重复 |
|---|---|---|---|
| **Authz**（本项目自研） | mode=authenticate/authorize, appCode | **singleton：一条路由只能挂一个** | 否 |
| **RequestRateLimiter**（本项目 MemoryRateLimiter） | replenishRate, burstCapacity, ... | singleton | 否 |
| AddRequestHeader | name, value | — | **可重复** |
| AddResponseHeader | name, value | — | **可重复** |
| SetRequestHeader / RemoveRequestHeader | name[, value] | 一般一个 | 一般一个 |
| StripPrefix | parts | 一个 | 否 |
| PrefixPath | prefix | 一个 | 否 |
| RewritePath | regexp, replacement | 一个 | 否 |
| SetPath | template | 一个 | 否 |
| SetStatus | code | 一个 | 否 |
| RedirectTo | status, url | 一个 | 否 |
| CircuitBreaker | name, fallback | 一个 | 否 |
| RequestSize | maxSize | 一个 | 否 |
| Retry | retries, statuses, methods | 一个 | 否 |
| TokenRelay（OAuth2） | 无参 | singleton | 否 |

全局级（GlobalFilter，跨所有路由，带 order）：

| 全局过滤器 | 参数 | order 约定 |
|---|---|---|
| 真实 IP 解析（X-Forwarded-For） | 信任网段 | 很高（最先） |
| 灰度/金丝雀路由 | 规则 | 中 |
| 跨域 CORS 配置 | allowedOrigins... | 高 |
| 访问日志/链路追踪 traceId | 采样率 | 高 |
| 响应统一包装/异常处理 | 错误码映射 | 很低（最后） |

## 2. 页面交互语义（回答第 5 点）

整理下来一共四种"配置形态"，前端按字典表 `args_schema_json` 渲染即可：

| 形态 | 含义 | 例子 | 前端控件 |
|---|---|---|---|
| **scalar-required** | 必须填，不填不让提交 | route.uri、jwt.secret、Authz 的 mode+appCode | 输入框 + 必填红星 |
| **scalar-optional-singleton** | 最多一个，可不填 | server.port、retry.retries | 输入框，留空走代码默认值 |
| **singleton-per-route** | 一条路由/一个作用域下**只准出现一次**，重复提交要拦截 | Authz、RequestRateLimiter、StripPrefix、TokenRelay | 下拉里灰掉已挂过的工厂；或表单直接单例 |
| **list-repeatable** | 同一个过滤器可挂 N 次 | AddRequestHeader、AddResponseHeader、多个 Header 断言、permit-all 路径 | 动态行表格，可"添加一行/删除一行" |

另外两个边界规则也放进字典，不靠前端硬编码：

- `is_required_args`：过滤器的哪些参数必填（Authz 有参，TokenRelay 无参）。
- `is_sensitive`：值加密落库、页面掩码（jwt.secret、client-secret、datasource.password）。
- `is_textarea`：SQL 这种大文本单独大框。

## 3. 表结构总览（9 张表，`gw_` 前缀）

```
gw_config_profile        环境（dev/test/prod），决定导出到哪个 consul/nacos
gw_config_item           全局 key-value 配置（按 profile 隔离）
gw_route                 路由（每个下游服务一行）
gw_route_predicate        路由断言（1 路由 : N 断言）
gw_route_filter           路由过滤器（1 路由 : N 过滤器，sort_num 定顺序）
gw_global_filter          全局过滤器（跨路由，order_num 定顺序）
gw_filter_definition      过滤器字典（工厂元数据 + 动态表单 schema）
gw_predicate_definition   断言字典
gw_config_publish         发布记录（导出 yaml/推配置中心的审计与回滚快照）
```

设计取舍：

1. **过滤器/断言的参数用 `args_json` 存 JSON**，不搞 EAV 竖表——SCG 每个工厂参数数量、类型都不一样，竖表 join 爆炸；JSON 导出时再按工厂名翻译成 `FilterName=k1:v1,k2:v2` 或 yaml map。
2. **`gw_filter_definition.args_schema_json` 是驱动前端动态表单的唯一事实来源**：加新过滤器 = 字典插一行 + 后端注册 FactoryBean，前端零代码。
3. **路由不按环境拆**：uri 一律写 `lb://service-name`，环境差异交给 discovery/配置中心；只有全局标量配置（数据库地址、JWT secret、端口）才按 `gw_config_profile` 隔离。
4. **软删 `del_flag` + 唯一键不含 del_flag**，沿用 basic_* 那套（重复启用走 UPDATE 复活）。

## 4. 关键表字段速览

### gw_route
`id, route_code(唯一), route_name, app_code, uri, order_num, metadata_json, status, del_flag, remark, created_at, updated_at`

### gw_route_predicate
`id, route_id, predicate_name, args_json, sort_num, status, del_flag`

### gw_route_filter
`id, route_id, filter_name, args_json, sort_num, status, del_flag`

### gw_global_filter
`id, filter_name, args_json, order_num, enabled, status, del_flag, remark`

### gw_filter_definition
`id, factory_name, display_name, scope(ROUTE/GLOBAL/BOTH), singleton_per_route, args_schema_json, builtin, status`

`args_schema_json` 长这样：
```json
[
  {"key":"mode","label":"鉴权模式","type":"enum","required":true,
   "options":["authenticate","authorize"],"default":"authenticate"},
  {"key":"appCode","label":"应用编码","type":"select_app","required":true}
]
```

### gw_config_profile
`id, profile_code(dev/test/prod), profile_name, center_type(FILE/CONSUL/NACOS), center_address, data_id, group_name, status`

### gw_config_item
`id, profile_id, config_group, config_key(与 profile_id 联合唯一), config_value, value_type, is_encrypted, is_required, sort_num, remark`

### gw_config_publish
`id, profile_id, center_type, target_desc, snapshot_json, operator, status(SUCCESS/FAIL), error_msg, created_at`

完整 DDL + 字典种子数据见 `gw_schema_mysql.sql`。
