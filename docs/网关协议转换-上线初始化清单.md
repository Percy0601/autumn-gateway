# 网关协议转换（HTTP → Thrift）— 上线初始化清单

> 用途：这份文件专门记「上线时要一并执行的 DDL + 菜单初始化语句」。
> 用户口径：**这些语句不要丢，项目上线时一起初始化**，与 gw_* 既有表、既有网关菜单的初始化方式保持一致。
>
> 关联代码：
> - 网关侧 starter：`autumn-gateway-starters/thrift-autumn-gateway-starter`
> - dashboard 实体/接口：`GwThriftService`、`GwThriftConversion`、`GwThriftController`、`GwThriftConfigService`
> - dashboard-ui 页面：`src/views/gateway/thrift/index.vue`（菜单：网关配置 → 协议转换）
> - 三份 DDL 已同时落进 `autumn-gateway-dashboard/src/main/resources/db/gateway/gw_schema_{mysql,postgresql,h2}.sql`

## 1. 与 Apache ShenYu（HTTP → Dubbo）的对应关系

| ShenYu | 我们（HTTP → Thrift） | 落点 |
|---|---|---|
| Plugin（dubbo）+ selector/rule（URI/Header/Query/Cookie 匹配） | SCG 路由 + `Path/Header/Query` Predicate | `gw_route` 既有能力，不新增 |
| Metadata（serviceName / methodName / parameterTypes） | `gw_thrift_service`：服务地址 + IDL（免接口 jar） | 新表 |
| RpcParamTransformPlugin + param-mapping | `gw_thrift_conversion`：`arguments_json`（BODY/QUERY/HEADER/PATH/FIXED）+ `response_mode` | 新表 |
| GenericService 泛化调用 | `GenericThriftInvoker`（IDL 驱动，`autumn-protocol-extension`） | 已实现，P0 已验通 |
| admin 落库 → 数据同步 → 网关内存 | dashboard 落库 → `GwConfigSyncService` 导出 `autumn.thrift.*` → Consul/Nacos → 网关启动加载 | 已接上（P0 首版） |

差异：ShenYu 靠注册中心 + 注解自动注册 metadata；我们 P0 先用"页面手填服务 + IDL"，P2 再做注册中心/热注册。

## 2. 表结构：不需要单独执行 DDL

两件事已经由启动流程兜住了，**不用再手工贴 DDL**：

1. 新库：`spring.sql.init.schema-locations` 里的 `db/gateway/gw_schema_{dialect}.sql`
   用 `CREATE TABLE IF NOT EXISTS` 建表；
2. 存量库：唯一升级脚本 `db/upgrade/upgrade-to-latest.sql` 的 `@@STEP 100`（见 §3），
   由 `SchemaUpgradeRunner` 在启动时按台账执行一次。

> 因此本文不再复制 DDL 正文 —— 复制就一定会漂移。
> 表定义只有两个来源：`db/gateway/gw_schema_*.sql`（新库）和
> `db/upgrade/upgrade-to-latest.sql` 的 STEP 100（存量库）。

## 3. 菜单与角色授权：同样不需要手工执行

「网关配置 → 协议转换」（`menu_identification='gateway:thrift'`）以及给管理员角色
（`basic_role.master=1`，含 SUPER_ADMIN / admin）的授权，都已写成升级脚本里的
`@@STEP 101` / `@@STEP 102`，启动时自动补齐、幂等不重复。

升级机制（为什么一个文件就够、为什么不会插重数据）见 `db/upgrade/README.md`。

需要人工核对时执行：

```sql
-- 菜单是否就位（期望 parent_id = 网关配置目录 id、menu_status=1、del_flag=0）
SELECT id, parent_id, menu_name, menu_url, menu_status, del_flag
FROM basic_menu WHERE menu_identification = 'gateway:thrift';

-- 授权是否就位
SELECT p.role_id, r.code, p.ref_id, p.type
FROM basic_role_permission p JOIN basic_role r ON r.id = p.role_id
WHERE p.ref_id = (SELECT id FROM basic_menu WHERE menu_identification = 'gateway:thrift');

-- 台账：三段是否已执行
SELECT step_id, step_name, dialect, applied_at FROM basic_schema_version ORDER BY step_id;
```

> dashboard-ui 侧 `src/store/modules/router.ts` 的静态兜底菜单里保留了
> `{ id: 38, name: '协议转换', url: 'gateway/thrift/index', icon: 'swap' }`，
> 但**只有后端菜单接口不可用时才会用到**。正常情况下菜单以 `basic_menu` 为准 ——
> 这也正是之前「admin 看不到入口」的原因：库里没有这行菜单。

## 4. 上线顺序（建议，已简化）

1. 确认 `autumn.dashboard.db-upgrade.enabled` 未被人为关掉（默认 true），启动一次即完成建表 + 菜单 + 授权；
2. 若数据库账号无 DDL 权限，改为人工执行 `db/upgrade/upgrade-to-latest.sql`（幂等，可重复）；
3. 网关侧打开开关并下发配置（任选其一）：
   - 手工：`autumn.thrift.enabled=true` + `autumn.thrift.services[]` + `autumn.thrift.mappings[]`；
   - dashboard：「协议转换」页配置服务与规则 → 「配置同步」页预览/推送 Consul / Nacos（导出块已并入 `autumn.thrift.*`）；
4. 路由上挂过滤器：`ThriftGeneric=<service>,<method>,<conversion_code>`（service/method 可省略走动态分发）；
5. 验证：`curl --noproxy '*' -X POST http://<gateway>/thrift/DemoService/echo -H 'Content-Type: application/json' -d '{"name":"x"}'`。

## 5. 回滚

1. 路由上去掉 `ThriftGeneric` 过滤器（HTTP 路由不受影响）；
2. `autumn.thrift.enabled=false`（默认值，等于关掉）；
3. 表与菜单保留即可（无代码引用时零影响）；如需彻底清理：
   `DELETE FROM basic_menu WHERE menu_identification='gateway:thrift';`
   `DROP TABLE gw_thrift_conversion; DROP TABLE gw_thrift_service;`
