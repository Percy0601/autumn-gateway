# 本地启动与测试顺序（Windows）

> 适用：autumn-gateway 三服务联调。最后验证时间：2026-10-22
> 端口分配：authorization **:9000** → dashboard **:8081** → gateway **:8080**（浏览器只认 8080）

---

## 一、启动顺序（严格按这个，不能乱）

```
① MySQL（远程 102 虚拟机，不是本地进程）
      ssh percy@192.168.0.102
      docker start mysql
      验证：mysql -h192.168.0.102 -uroot -p123456 -e "show databases;"
      库里要有 autumn-security

② authorization :9000   ← IdP，必须最先起
      cd D:\work\project\autumn-gateway
      .\mvnw.cmd -pl autumn-gateway-authorization spring-boot:run

③ dashboard :8081       ← 业务后端，连 MySQL + 拉 authorization 的 JWKS
      .\mvnw.cmd -pl autumn-gateway-dashboard spring-boot:run

④ gateway :8080         ← 最后起，统一入口，转发到 dashboard
      .\mvnw.cmd -pl autumn-gateway-deploy spring-boot:run

⑤ 前端 dashboard-ui
      方式 A（联调验证，推荐）：不用单独起，直接浏览器开 http://localhost:8080/
      方式 B（改前端代码时）：cd autumn-gateway-dashboard-ui; npm install; npm run dev
```

> ⚠️ 纠正一个常见误解：**dashboard 不是最后起的**。gateway(:8080) 要把请求转发到
> dashboard(:8081)，所以 dashboard 必须在 gateway **之前**起来。authorization 又必须在
> dashboard 之前，因为 dashboard 启动时要去 9000 拉 JWKS 公钥。

---

## 二、为什么是这个顺序（依赖关系）

| 步骤 | 谁依赖谁 | 起不来的症状 |
|---|---|---|
| ② authorization | 只依赖 MySQL | 9000 起不来，后面全瘫 |
| ③ dashboard | MySQL + authorization(JWKS) | 报 `invalid_token` / 拉不到 jwks |
| ④ gateway | authorization(跳转登录) + dashboard(转发) | 登录后回 8080 白屏或 502 |
| ⑤ 前端 | gateway:8080 | 直连 8081 会绕过认证 |

## 三、验证步骤（浏览器点一遍）

1. 打开 **http://localhost:8080/**（不要开 8081，不要开 9000）
2. 自动 302 跳到 **http://localhost:9000/login**
3. 输入账号 **admin** / 密码 **Autumn@123456** + 验证码
4. 自动回跳 **http://localhost:8080/**，进入 dashboard 首页
5. 按 F12 → Application → Cookies：**应该只有一枚 `SESSION`（HttpOnly），没有 token**
6. 右上角「退出登录」→ 跳回 9000 登录页

成功标准（对照手册附录 C）：
- 未登录访问 8080 → 302 到 9000
- 登录后 `/api/currentUser` → 200，返回 `authorityList`（权限码清单）
- 退出后 `/api/currentUser` → 401

## 四、Windows 环境注意事项

### 1. JAVA_HOME 必须是 JDK 25
这个项目基线是 **Java 25 / Spring Boot 4.1.1**，**不能用 JDK 8**（JDK 8 是另一个 scm-back 项目的）。
确认：
```powershell
java -version    # 要显示 25.x
```
如果不对，启动前先切：
```powershell
$env:JAVA_HOME = "D:\opt\Java\jdk-25"   # 按你实际路径
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
```

### 2. 端口被抢成 64884？清 SERVER__PORT
手册里的 `env -u SERVER__PORT` 是 macOS 语法，Windows 等价：
```powershell
Remove-Item Env:SERVER__PORT -ErrorAction SilentlyContinue
```
如果启动后日志显示端口不是 9000/8081/8080 而是随机高位端口，就是这个变量在作怪。

### 3. 验证码
默认开启。跑自动化脚本测试时，启动命令末尾加：
```
--autumn.security.captcha.enabled=false
```

### 4. 三个窗口
建议开三个 PowerShell 窗口，每个跑一个服务，日志分开看，方便排障。

## 五、常见起不来的排查

| 症状 | 先看哪个 |
|---|---|
| dashboard 启动报 `JdbcAggregateOperations` 连环错 | MySQL 没起或连不上。先 `Test-NetConnection 192.168.0.102 -Port 3306` |
| 登录后回 8080 又跳回 9000 登录页 | 账号密码错或验证码没过，看 9000 日志 |
| `/api/**` 返回登录页 HTML 而不是 401 | 前端请求没带 `Accept: application/json` 或没带 Cookie（withCredentials） |
| 网关报 `code_challenge` 相关错 | PKCE 没开（starter 里 `requireProofKey(true)`） |
| 回调报 `invalid_redirect_uri` | 回调地址没在 `oauth2_registered_client` 登记 |
| 直连 8081 能进但走 8080 不行 | 你绕过了网关认证，**这是错的用法**，必须从 8080 进 |

---

## 六、一句话速记

> **MySQL → 9000(IdP) → 8081(dashboard) → 8080(网关) → 浏览器开 8080**
