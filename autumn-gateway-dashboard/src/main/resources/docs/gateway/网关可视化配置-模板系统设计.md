# 网关可视化配置 — 模板系统设计（v2）

> 本设计回答的问题：**如何让网关可视化配置不是「简单 key-value 输入」，而是「可自定义模板 + 配置项提示 + 支持 list / map / 嵌套 object / 一个或多个配置项」的模板化配置**，覆盖绝大多数 Spring Cloud Gateway（SCG 5.0.3）配置。
>
> 配套产物：
> - DDL：三份 `db/gateway/gw_schema_{mysql,postgresql,h2}.sql` 各追加 5 张新表（§3）。
> - 种子数据：`db/gateway/gw_template_seed.sql`（MySQL 方言，兼容 H2 MODE=MySQL；PostgreSQL 适配见 §5.4）。
> - 本文档替代《网关可视化配置-表结构设计.md》§6.1 中「模板 schema 放代码侧静态注册表」的结论——本设计把模板落库，因为需求明确要求「用户可自定义模板、不改代码不发版」。

## 0. 结论摘要（先读这个）

**方向可行，但原 6 表设计有 4 处硬伤，按原样落地会在 `cors-configuration` 这类嵌套 map 上失败。** 修正后共 5 张表：

| 原设计（6 表） | 修正后（5 表） | 变化 |
|---|---|---|
| `filter_definition` | `gw_tpl_definition`（kind=FILTER/PREDICATE/STRUCT） | 合并过滤器+断言为一张表，新增 STRUCT 类别（承接 globalcors 等**非过滤器**的结构化全局配置）；补 `category/builtin/singleton_per_route/status` |
| `filter_definition_detail` | `gw_tpl_field` | 补 `label/required/options_json/placeholder/validator/sensitive/is_map_key/map_key_validator/export_key`；`key_type`+`value_type` 合并为 `value_type_id` |
| `filter_type_definition` | `gw_value_type` | 保留（值类型目录），kind 收窄为 BASIC/LIST/OBJECT |
| `filter_type_definition_detail` | `gw_value_type_field` | **改为自引用递归结构**（role=ITEM/FIELD），可表达 LIST 的元素类型、OBJECT 的字段；`key_type/value_type` 两列删掉，改为 `value_type_id` 递归引用 |
| `filter_predicate_definition` | → `gw_tpl_definition`（kind=PREDICATE） | **删掉 `filter_id`**——断言不是过滤器的子集，是独立命名空间 |
| `filter_predicate_definition_detail` | → `gw_tpl_field`（tpl 指向 PREDICATE 模板） | 同上 |
| （无） | `gw_config_struct` | 新增：STRUCT 模板的实例落点（globalcors / httpclient 这类带前缀的结构化配置） |

**本次源码核对发现的问题种子**（新种子已纠正，旧 `GwDataInitializer` 里是错的）：

| 旧种子 | 问题（对照 5.0.3 sources.jar） | 新种子 |
|---|---|---|
| `Cors` 过滤器模板（args=`corsConfiguration`） | **5.0.3 没有 `CorsGatewayFilterFactory`**，CORS 由 `globalcors` 全局属性 + CorsWebFilter 处理 | 改为 `globalcors` STRUCT 模板（§5.3） |
| `SetStatus` 带 `reason` 参数 | `SetStatusGatewayFilterFactory.Config` 只有 `status` | 只留 `status` |
| `RequestRateLimiter` 模板（replenishRate/burstCapacity…） | 那是 Redis 限流工厂；本仓库实际是 `MemoryRateLimiterGatewayFilterFactory` | 改名为 `MemoryRateLimiter` |
| `RequestHeaderToRequestUri` 带 `expression` 参数 | 实际继承 `NameConfig`，arg 只有 `name` | 只留 `name` |

> 参数核对依据：`spring-cloud-gateway-server-webflux-5.0.3-sources.jar` 各工厂 Config 类字段 + `CorsConfiguration`（spring-web 7.0.9）。所有种子参数（§5.2/§5.3）均以此为准，不是凭记忆。

## 1. 需求拆解：模板系统必须能表达什么

| # | 能力 | 说明 | 对应设计 |
|---|---|---|---|
| 1 | 模板不是裸 KV | 选模板 → 按配置项渲染表单 | `gw_tpl_definition` + `gw_tpl_field` |
| 2 | 配置项有提示 | label / 占位提示 / 默认值 / 枚举 / 说明 | `gw_tpl_field.label / placeholder / default_value / options_json / remark` |
| 3 | 一个或多个配置项 | 同一模板可有 1..N 个配置项 | `gw_tpl_field` 1:N 行 |
| 4 | 标量 | string/int/long/bool/duration/size/enum/sensitive… | `gw_value_type`（BASIC） |
| 5 | list | 多值（HTTP 方法、CIDR 段、状态码…） | `gw_value_type`（LIST）+ ITEM 行 |
| 6 | map | 键由用户输入、可校验（如 CORS 路径模式 `/**`） | `gw_tpl_field.is_map_key + map_key_validator` |
| 7 | 嵌套 object | map 的值 / list 的元素本身带多个字段（CORS 8 字段、Retry backoff 4 字段） | `gw_value_type`（OBJECT）+ FIELD 行，**递归** |
| 8 | 模板可自定义 | 用户新增/修改模板，不改代码不发版 | `builtin` 区分内置/自定义 + 模板 CRUD |
| 9 | 实例化落 route / global | 模板 → 路由断言 / 路由过滤器 / 全局过滤器 / 结构化全局配置 | 复用 `gw_route_predicate / gw_route_filter / gw_global_filter` + 新增 `gw_config_struct` |

## 2. 原 6 表设计评审

### 2.1 硬伤（不修正就无法达成目标）

**P1-1 `filter_predicate_definition(id, filter_id, ...)` —— filter_id 语义错误**
断言（Path/Method/Header…）与过滤器（StripPrefix/Retry…）是**两个独立命名空间**，断言不属于任何过滤器。带 `filter_id` 会导致两种错误做法：要么每个过滤器各复制一份 Path 模板（数据爆炸），要么强行挂到某个过滤器下（语义混乱）。→ 修正：合并为一张 `gw_tpl_definition`，`kind` 区分；断言模板 `scope` 恒为 ROUTE、无 singleton 概念。

**P1-2 `filter_type_definition_detail(id, key_type, key_name, value_type, desc)` —— 只能表达一层，CORS 表达不了**
`cors-configurations` 的真实结构是 `Map<String, CorsConfiguration>`，其中 `CorsConfiguration` 有 8 个字段（`allowedOrigins`/`allowedMethods`/`allowedHeaders`/`exposedHeaders`/`allowedOriginPatterns`/`allowCredentials`/`allowPrivateNetwork`/`maxAge`），且前 5 个是 **list**。你的类型明细表是「key → value 标量」一层平铺，没有「类型的字段可以再引用另一个类型」的递归，也没有「list 的元素类型」的落点。→ 修正：`gw_value_type_field` 用 `value_type_id` **自引用** `gw_value_type`，`role` 区分 ITEM（list 元素）与 FIELD（object 字段），深度不限（CORS 是 2 层）。

**P1-3 缺 STRUCT 类别 —— `globalcors` 不是过滤器，6 表里没有它的家**
SCG 里 CORS 不是 `GatewayFilterFactory`，是顶层属性 `spring.cloud.gateway.server.webflux.globalcors.*`（`GlobalCorsProperties.corsConfigurations: Map<String, CorsConfiguration>`）。旧设计里 `filter_definition.support_global` 只能表达「全局默认过滤器」，表达不了带前缀路径的全局属性。→ 修正：`kind=STRUCT` + 实例表 `gw_config_struct`（§3.5、§6.3 导出）。

**P1-4 缺导出路径模型 —— 模板不携带「如何变成 properties」就无法导出**
SCG 导出有三类形态，模板必须各自携带路径语义才能翻译：
- 过滤器/断言参数：`routes[i].filters[j].args.xxx=yyy`（args 是 `Map<String,String>`）
- 嵌套对象：点号展开（Retry 的 `backoff.firstBackoff=5ms`，见 `shortcutFieldOrder()`）
- STRUCT 的 map：`globalcors.cors-configurations['/**'].allowed-origins`
→ 修正：每个配置项带 `export_key`（默认=key_name），OBJECT 字段按层级点号拼接，map 键走 `[key]` 后缀（§6.3）。

### 2.2 次要点（不阻塞，但建议改）

- **P2-1** `key_type` / `value_type` 语义重叠：两个列名含义不清晰，且缺「枚举候选项 / 正则校验 / 必填 / 敏感 / 中文 label / 占位提示」。→ 统一为 `value_type_id` + 独立的表单元数据列。
- **P2-2** 缺 `singleton_per_route`（同一路由该模板只准挂一次 vs 可挂多次——现有 `gw_filter_template` 已有此概念，新设计必须保留）。
- **P2-3** 缺 `builtin`：种子模板与用户自定义模板不加区分，就无法保护内置模板不被误删/误改。
- **P2-4** `support_global / support_router` 两个布尔 → 改为 `scope` 单列（ROUTE/GLOBAL/BOTH），与现有 `gw_filter_template.scope` 口径一致，STRUCT 恒为 GLOBAL。

### 2.3 可行性结论

| 目标 | 原 6 表 | 修正后 |
|---|---|---|
| 配置 route_predicate（Path/Method/Header…） | ✅（但模板与实例的翻译规则未定义） | ✅ |
| 配置 route/global 过滤器（含一次/多次语义） | ✅（缺 singleton） | ✅ |
| `cors-configuration` 这类 map 复杂类型 | ❌（一层平铺 + 无 STRUCT 落点） | ✅（MAP 键校验 + OBJECT 递归 + gw_config_struct） |
| 用户自定义模板、不发版 | ✅（模板表 + CRUD 即可） | ✅（+ builtin 保护） |
| 绝大多数 SCG 配置 | ❌（httpclient/globalcors 等全局属性无落点） | ✅（STRUCT 类别 + 类型目录） |

## 3. 修正设计：5 张表

> 全部走 `gw_` 前缀（与现有 8 张 gw 表一致）；时间列、`sort_num`、`status`、`del_flag` 语义沿用现有约定。

### 3.1 `gw_tpl_definition` — 模板定义（对应原 filter_definition / filter_predicate_definition）

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK | |
| `kind` | VARCHAR(16) | **FILTER / PREDICATE / STRUCT**。FILTER=过滤器工厂（挂 route/global）；PREDICATE=断言工厂（挂 route）；STRUCT=结构化全局属性（globalcors 等） |
| `name` | VARCHAR(64) | FILTER/PREDICATE 为工厂短名（如 `Retry`/`Path`）；STRUCT 为逻辑名（如 `globalcors`）。**UNIQUE(kind, name)** |
| `display_name` | VARCHAR(64) | 页面显示名，如「重试」「跨域 CORS」 |
| `category` | VARCHAR(32) | 选择器分组：`鉴权 / 限流 / 路径 / 头操作 / 重写 / 重试熔断 / 安全 / 其他 / 结构化全局` |
| `scope` | VARCHAR(16) | FILTER：ROUTE/GLOBAL/BOTH；PREDICATE：恒 ROUTE；STRUCT：恒 GLOBAL |
| `singleton_per_route` | TINYINT | 1=同路由最多挂一次（Authz/StripPrefix/Retry…）；0=可挂多次（AddRequestHeader…）。仅 FILTER 有意义 |
| `builtin` | TINYINT | 1=内置种子模板（前端只读/复制，不允许删改）；0=用户自定义 |
| `sort_num` | INT | 选择器内排序 |
| `status` | TINYINT | 1=启用（可被选择）0=停用 |
| `remark` | VARCHAR(512) | 模板说明（含依赖提示：如 CircuitBreaker 需 resilience4j） |
| `created_at / updated_at` | DATETIME | |

### 3.2 `gw_tpl_field` — 模板配置项（对应原 filter_definition_detail / filter_predicate_definition_detail）

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK | |
| `tpl_id` | BIGINT FK→gw_tpl_definition.id | 所属模板 |
| `key_name` | VARCHAR(64) | 配置项 key：FILTER/PREDICATE 为 args key（如 `backoff`）；STRUCT 为属性段（如 `corsConfigurations`） |
| `label` | VARCHAR(64) | 中文提示，表单 label |
| `value_type_id` | BIGINT FK→gw_value_type.id | 值类型（标量/list/object），递归 |
| `required` | TINYINT | 1=必填，实例化时校验 |
| `default_value` | VARCHAR(255) | 默认值（前端预填，留空=不预填） |
| `options_json` | TEXT | ENUM 的候选项 JSON 数组（`["authenticate","authorize"]`）；**map 键为固定集合时**也用它（前端渲染为下拉而非自由输入） |
| `placeholder` | VARCHAR(255) | 输入占位提示（如 `/api/order/**`、`500ms`） |
| `validator` | VARCHAR(255) | 值正则（Java/JS 双端校验，如 CIDR、ISO8601） |
| `sensitive` | TINYINT | 1=敏感（掩码显示） |
| `is_map_key` | TINYINT | **1=该配置项实例值为 Map**：键由用户输入，值类型=`value_type_id`；0=普通标量/list/object |
| `map_key_validator` | VARCHAR(255) | map 键的正则（如 CORS 路径模式 `^/[\w*/{}.()-]*$`）；`options_json` 非空时忽略（键为固定下拉） |
| `export_key` | VARCHAR(128) | 导出路径段，默认=key_name；STRUCT 模板里常用 kebab-case（如 `allowed-origins`） |
| `sort_num` | INT | 表单内顺序 |
| `remark` | VARCHAR(512) | 该项说明（tooltip） |

### 3.3 `gw_value_type` — 值类型目录（对应原 filter_type_definition）

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK | |
| `name` | VARCHAR(64) | 唯一名，如 `STRING` / `LIST_HTTP_METHOD` / `OBJECT_CORS` |
| `display_name` | VARCHAR(64) | 如「字符串 / HTTP 方法列表 / CORS 配置对象」 |
| `kind` | VARCHAR(16) | **BASIC / LIST / OBJECT** |
| `builtin` | TINYINT | 1=内置类型（受保护）0=用户自定义 |
| `sort_num` | INT | |
| `status` | TINYINT | 1=启用 |
| `remark` | VARCHAR(512) | |

- **BASIC**：叶子类型，无子行。内置 `STRING / INT / LONG / DOUBLE / BOOL / DURATION / SIZE / ENUM / DATETIME / TEXTAREA / SENSITIVE`。
- **LIST**：`gw_value_type_field` 一行 `role=ITEM`，`value_type_id`=元素类型。
- **OBJECT**：`gw_value_type_field` 多行 `role=FIELD`，每行一个字段（字段本身也可是 LIST/OBJECT/带 is_map_key 的 map → **无限递归**）。

### 3.4 `gw_value_type_field` — 复合类型结构（对应原 filter_type_definition_detail，改为递归）

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK | |
| `type_id` | BIGINT FK→gw_value_type.id | 所属复合类型 |
| `role` | VARCHAR(16) | `ITEM`=list 元素定义（每个 LIST 类型恰 1 行）；`FIELD`=object 字段定义 |
| `key_name` | VARCHAR(64) | ITEM 时固定 `ITEM`；FIELD 时为字段名（如 `firstBackoff`） |
| `label` | VARCHAR(64) | 中文名 |
| `value_type_id` | BIGINT FK→gw_value_type.id | **递归引用**：该位置的类型 |
| `required / default_value / options_json / placeholder / validator / sensitive / is_map_key / map_key_validator` | 同 3.2 | 与模板配置项同语义（嵌套层同样支持 map） |
| `export_key` | VARCHAR(128) | 导出路径段，默认=key_name；如 backoff 的 `firstBackoff`、CORS 的 `allowed-origins` |
| `sort_num` | INT | |
| `remark` | VARCHAR(512) | |

### 3.5 `gw_config_struct` — 结构化全局配置实例（STRUCT 模板的落点）

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK | |
| `profile_code` | VARCHAR(32) | 环境隔离（同 `gw_config_item`） |
| `struct_name` | VARCHAR(64) | 模板名（如 `globalcors`） |
| `instance_name` | VARCHAR(128) | 实例显示名（如「全局跨域策略」） |
| `value_json` | TEXT | **树形 JSON**（含 map 键、嵌套 object/list），按模板校验 |
| `sort_num` | INT | |
| `status` | TINYINT | 1=启用（导出）0=停用 |
| `del_flag` | TINYINT | 软删 |
| `remark` | VARCHAR(512) | |
| `created_at / updated_at` | DATETIME | |

> 复用既有实例表：PREDICATE→`gw_route_predicate`、FILTER(route)→`gw_route_filter`、FILTER(global)→`gw_global_filter`，它们的 `args_json` 语义从「平铺 Map」升级为「树形 JSON」，导出时按模板展开（§6）。

## 4. 类型目录模型与两个展开示例

### 4.1 CORS：MAP → OBJECT → LIST 字段（你要的 cors-configuration）

```
gw_value_type OBJECT_CORS (kind=OBJECT)
  ├─ FIELD allowedOrigins        value_type=LIST_STRING      export_key=allowed-origins
  ├─ FIELD allowedOriginPatterns value_type=LIST_STRING      export_key=allowed-origin-patterns
  ├─ FIELD allowedMethods        value_type=LIST_HTTP_METHOD export_key=allowed-methods
  ├─ FIELD allowedHeaders        value_type=LIST_STRING      export_key=allowed-headers
  ├─ FIELD exposedHeaders        value_type=LIST_STRING      export_key=exposed-headers
  ├─ FIELD allowCredentials      value_type=BOOL             export_key=allow-credentials
  ├─ FIELD allowPrivateNetwork   value_type=BOOL             export_key=allow-private-network
  └─ FIELD maxAge                value_type=LONG             export_key=max-age

gw_tpl_definition  globalcors (kind=STRUCT, scope=GLOBAL, builtin=1)
  └─ gw_tpl_field corsConfigurations  label=跨域配置   is_map_key=1
       map_key_validator='^/[\w*/{}.()-]*$'   (路径模式，如 /**, /api/**)
       value_type=OBJECT_CORS   export_key=cors-configurations
  └─ gw_tpl_field addToSimpleUrlHandlerMapping  label=预检直通  type=BOOL
       export_key=add-to-simple-url-handler-mapping
```

实例 JSON（`gw_config_struct.value_json`）：
```json
{
  "corsConfigurations": {
    "/**": { "allowedOrigins": ["https://docs.spring.io"], "allowedMethods": ["GET","POST"], "allowCredentials": true, "maxAge": 30 },
    "/api/**": { "allowedHeaders": ["*"] }
  },
  "addToSimpleUrlHandlerMapping": true
}
```

导出（properties，§6.3 规则）：
```properties
spring.cloud.gateway.server.webflux.globalcors.add-to-simple-url-handler-mapping=true
spring.cloud.gateway.server.webflux.globalcors.cors-configurations['/**'].allowed-origins=https://docs.spring.io
spring.cloud.gateway.server.webflux.globalcors.cors-configurations['/**'].allowed-methods=GET,POST
spring.cloud.gateway.server.webflux.globalcors.cors-configurations['/**'].allow-credentials=true
spring.cloud.gateway.server.webflux.globalcors.cors-configurations['/**'].max-age=30
spring.cloud.gateway.server.webflux.globalcors.cors-configurations['/api/**'].allowed-headers=*
```

### 4.2 Retry：过滤器里嵌套 OBJECT，导出点号展开

```
gw_tpl_definition  Retry (kind=FILTER, scope=ROUTE, singleton_per_route=1)
  ├─ field retries   INT   default 3
  ├─ field series    LIST (ITEM=ENUM: INFORMATIONAL/SUCCESS/REDIRECTION/CLIENT_ERROR/SERVER_ERROR)
  ├─ field statuses  LIST_INT        (提示：500,502,503)
  ├─ field methods   LIST_HTTP_METHOD default GET
  ├─ field backoff   OBJECT_BACKOFF  ── FIELD firstBackoff(DURATION, 5ms) / maxBackoff(DURATION)
  │                                   ── FIELD factor(INT, 2) / basedOnPreviousValue(BOOL, true)
  ├─ field jitter    OBJECT_JITTER   ── FIELD randomFactor(DOUBLE, 0.5)
  └─ field timeout   DURATION
```

实例 JSON（`gw_route_filter.args_json`）：
```json
{ "retries": 3, "statuses": [500, 502], "methods": ["GET"], "backoff": { "firstBackoff": "5ms", "factor": 2 } }
```

导出（点号展开）：
```properties
spring.cloud.gateway.server.webflux.routes[0].filters[1].name=Retry
spring.cloud.gateway.server.webflux.routes[0].filters[1].args.retries=3
spring.cloud.gateway.server.webflux.routes[0].filters[1].args.statuses=500,502
spring.cloud.gateway.server.webflux.routes[0].filters[1].args.methods=GET
spring.cloud.gateway.server.webflux.routes[0].filters[1].args.backoff.firstBackoff=5ms
spring.cloud.gateway.server.webflux.routes[0].filters[1].args.backoff.factor=2
```

> 依据：`RetryGatewayFilterFactory.shortcutFieldOrder()` 返回 `["retries","statuses","methods","backoff.firstBackoff","backoff.maxBackoff","backoff.factor","backoff.basedOnPreviousValue","jitter.randomFactor","timeout"]` —— 官方自己就是点号展开，说明 args 只能扁平化，嵌套对象必须拼键。

## 5. 种子模板初始化（本次已随 SQL 交付）

### 5.1 值类型目录（18 个内置）

| kind | name | 说明 |
|---|---|---|
| BASIC | STRING / INT / LONG / DOUBLE / BOOL | 基础标量 |
| BASIC | DURATION | 时长，如 `500ms` / `30s` / `2m` |
| BASIC | SIZE | 字节数，如 `5MB` / `16000B` |
| BASIC | ENUM / DATETIME / TEXTAREA / SENSITIVE | 枚举 / ISO8601+时区 / 大文本 / 敏感 |

## 6. 实例化与导出

### 6.1 模板 → 实例落点

| kind | 实例表 | 关键列 |
|---|---|---|
| PREDICATE | `gw_route_predicate` | predicate_name=模板 name，args_json=树形 JSON |
| FILTER(route) | `gw_route_filter` | filter_name=模板 name，args_json=树形 JSON，sort_num=链顺序 |
| FILTER(global) | `gw_global_filter` | 同上，进 default-filters |
| STRUCT | `gw_config_struct` | struct_name=模板 name，value_json=树形 JSON，按 profile 隔离 |

### 6.2 实例化校验（服务端 + 前端共用同一套 schema 规则）

1. `required=1` 且缺值 → 拦截；
2. 标量类型转换（INT/LONG/BOOL/DURATION…）失败 → 拦截；
3. ENUM 值不在 `options_json` → 拦截；
4. `validator` 正则不匹配 → 拦截；
5. `is_map_key=1`：map 键必须唯一、键通过 `map_key_validator`（或属于 `options_json`）；
6. 嵌套递归校验（OBJECT/LIST 按 `gw_value_type_field` 逐层下钻）。

### 6.3 导出规则（按 kind 分三类）

**A. FILTER / PREDICATE（进 `routes[i].filters[j]` / `predicates[j]`）**
```
<前缀>.routes[i].filters[j].name=<模板name>
<前缀>.routes[i].filters[j].args.<key>=<value>          # 标量
<前缀>.routes[i].filters[j].args.<key>=a,b,c            # LIST → 逗号拼接（SCG 反序列化要求）
<前缀>.routes[i].filters[j].args.<key>.<objField>=v     # OBJECT → 点号展开（递归）
<前缀>.routes[i].filters[j].args.<key>=<mapValue>       # is_map_key 且值为标量 → 直接取值
```
> `is_map_key` 用于过滤器/断言 args 时仅支持「map 值为标量」（args 是 `Map<String,String>`）；map 值为复合对象的场景只允许出现在 STRUCT 模板（如 CORS）。种子里没有把复合 map 放进 filter 模板，如需扩展须在导出器里明确「扁平化失败即报错」而非静默截断。

**B. STRUCT（进全局属性，带前缀）**
```
spring.cloud.gateway.server.webflux.<模板固定前缀>.<export_key>.<…>=<value>   # 逐层 export_key 拼接
# map 键： [key] 后缀；list： [i] 索引（避免逗号歧义，如值含逗号）
globalcors.cors-configurations['/**'].allowed-origins=https://a,https://b
globalcors.cors-configurations['/**'].allowed-methods[0]=GET
```

**C. 通用**
- 一律长写 `name= + args.xxx=`，不用短写（短写依赖 `shortcutFieldOrder`，逗号/冒号值错位）；
- 索引从 0 连续重编；`enabled=false` 的路由/过滤器也要导出（SCG 5 原生关闭）；
- yaml 导出时值一律加引号。

### 6.4 与旧方案的关系

- 旧 `gw_filter_template.args_schema_json` / `gw_predicate_template.args_schema_json`：**保留表不删**（前端/实体仍引用），新表 v2 上线且前端切版后再由迁移脚本删除/停用。
- 旧种子里的错误（§0 表格）在新种子已纠正；`GwDataInitializer` 的 Java 播种代码将在 §8 代码改造中替换为读取新表 + 幂等播种 v2 数据。

## 7. 自定义模板的约束与边界

| 项 | 规则 |
|---|---|
| 内置模板（builtin=1） | 前端只读；「编辑」= 复制为新模板（builtin=0）再改；不可删除 |
| 用户模板（builtin=0） | 全量 CRUD；改名冲突按 (kind, name) 唯一键拦截 |
| 新增过滤器工厂 | 仍然要改代码注册 Bean——**模板只能解决表单/导出元数据，不能凭空创造工厂**；页面新增模板时给出「自定义类型与真实工厂名必须一致」的提示 |
| 类型目录 | 用户可新增自定义 LIST/OBJECT 类型（自引用保证深度不限）；BASIC 内置类型不可改 |
| 校验 | 服务端存模板时校验：kind 合法、scope 与 kind 匹配（STRUCT→GLOBAL）、同模板内 key_name 不重复、value_type_id 存在且 kind 兼容（BASIC 只能被直接引用，LIST/OBJECT 引用无限制） |
